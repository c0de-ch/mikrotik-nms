# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

**MikroTik NMS** — a web-based network management tool for MikroTik RouterOS devices. Provides network topology visualization, real-time traffic monitoring, device health overview, and mass firmware management. Read-only monitoring with WinBox deep linking (`winbox://`) for device configuration. Full user management with admin/viewer roles.

## Build / Test / Lint Commands

- **Build all:** `make build` (outputs `bin/mikrotik-nms` + frontend `.next`)
- **Build backend only:** `make build-backend` or `cd backend && go build ./cmd/mikrotik-nms/`
- **Build frontend only:** `make build-frontend` or `cd frontend && npm run build`
- **Run backend (dev):** `make dev-backend` (requires `MIKROTIK_NMS_JWT_SECRET` env var; polls **nothing** — `MIKROTIK_NMS_POLLERS` defaults to `off`). To poll real lab devices: `MIKROTIK_NMS_ALLOWED_TARGET_CIDRS=<cidr,…> make dev-backend-poll`
- **Run frontend (dev):** `make dev-frontend`
- **Test:** `make test` or `cd backend && go test ./...`
- **Test single package:** `cd backend && go test -v ./internal/topology/ -run TestBuildLinks`
- **Lint:** `make lint` (runs `go vet` + `npm run lint`)
- **Docker:** `docker compose build` then `docker compose up -d`
- **K8s:** `kubectl apply -f deploy/k8s/` (edit `secret.yaml` and `ingress.yaml` first)
- **Dev (both):** `./scripts/dev.sh` starts backend + frontend concurrently
- **Fuzz the flow decoder:** `make fuzz-flow` (60 s of `FuzzDecode`; the seed corpus also runs in plain `go test`)
- **Replay synthetic flows (dev):** `cd backend && go run ./cmd/flowreplay -to 127.0.0.1:2055 -scenario lab` — RouterOS IPFIX from 127.0.0.2 + OPNsense NetFlow v9 from 127.0.0.3 (+ an unknown sender 127.0.0.4) with current timestamps; the backend needs `MIKROTIK_NMS_FLOW_LISTEN` and exporters for those addresses (`-mix` adds a multi-host mix of lab hosts talking to common internet services, `-skip-templates` tests persisted templates, `-dir` replays `MIKROTIK_NMS_FLOW_CAPTURE_DIR` captures)

## Architecture

Monorepo with Go backend + Next.js frontend communicating via REST API and WebSocket.

### Backend (`backend/`)

Go with `chi` router, SQLite (WAL mode) via `modernc.org/sqlite`, no ORM (raw SQL in `internal/database/queries/`).

- **`cmd/mikrotik-nms/main.go`** — entrypoint, wires config → DB → WebSocket hub → poller manager → HTTP server
- **`internal/config/`** — env-based configuration (`MIKROTIK_NMS_*` prefix), incl. the polling fence — `Pollers` (`MIKROTIK_NMS_POLLERS`: `local`|`off`, **code default `off` = no device or UDP I/O**) and `AllowedTargetCIDRs` (`MIKROTIK_NMS_ALLOWED_TARGET_CIDRS`: parsed `netip.Prefix` allow-list, **required with `local`**, invalid entries are startup errors) — `FlowListen` (`MIKROTIK_NMS_FLOW_LISTEN`: comma-separated UDP bind addresses, invalid entries logged + skipped, **empty = flow collector off**) and the dev-only `FlowCaptureDir`
- **`internal/database/`** — SQLite setup, goose migrations (`001_init.sql` … `025_device_findings.sql`; **strictly additive from 023 on** — the previous release's binary must run on the new schema, so new tables and nullable columns only, never drop/rename/re-key within a milestone), query functions. Tables: `users`, `devices` (incl. the P0-4 columns `device_class`/`class_override`/`class_probed_at`/`poll_profile`/`polling_paused_until`/`cpu_count`/`cpu_mhz_max`), `audit_log` (admin actions: pauses, profile and class-override changes), `device_findings` (per-device hygiene findings such as `parallel_api_poller`, upserted by kind+detail), `interfaces`, `neighbors`, `links`, `traffic_samples`, `firmware_status`, `upgrade_jobs`, `upgrade_job_devices`, `dns_servers`, `wifi_history`, `client_history`, `mac_lookup`, `app_settings`, `bridge_status`, `bridge_port_status`, `loop_events`, `interface_state`, `bridge_vlans`, `vlan_labels`, `password_reset_tokens`, `ping_targets`, `ping_samples`, `client_signal_samples`, `speed_tests`, `speed_samples`, `traceroute_runs`, `device_uplinks`, `port_stats_1m`, `port_stats_1h`, `port_hosts`, `interface_relations`, `flow_exporters`, `flow_exporter_ifaces`, `flow_points`, `flow_templates`, `flow_prefixes`, `flow_1m`, `flow_1h`, `flow_1m_meta`, `flow_1h_meta`
- **`internal/auth/`** — JWT (access 15min + refresh 7d), bcrypt passwords, chi middleware (`RequireAuth`, `RequireRole`)
- **`internal/routeros/`** — RouterOS API client pool wrapping `go-routeros/routeros/v3`. Functions for `/system/resource` (one proplisted print; `SystemResource.Fields` carries the CPU facts for the class probe), `/ip/neighbor`, `/interface/monitor-traffic`, the **one scheduled interface print** (`GetInterfaceStats`, Tier 0: `/interface/print` proplisted to `.id,name,type,mac-address,mtu,running,disabled,slave,comment,last-link-up-time,last-link-down-time,link-downs` + the rx/tx byte/packet/error/drop/`tx-queue-drop` counters; `IfIndexFromID` in `ifindex.go` turns its `.id` into the SNMP/flow-export ifIndex — `*D` → 13 — and `GetVLANInfo` reads `/interface/vlan` vlan-id + parent), the Tier 4a ethernet print (`GetEthernetStats` in `ethernet.go`: proplisted `/interface/ethernet/print` — loop-protect, flow control, switch chip, hardware drop/FCS/pause counters; `MergeEthernet` joins it by name into `InterfaceSnapshot` rows), `GetInterfaces` (proplisted `name,type,mac-address`, only for the IP auto-follow identity check), the bridge FDB (`GetBridgeHosts`: `/interface/bridge/host` `local=false`; no per-MAC FDB query exists any more), `/system/package/update`, the bridge/STP readers in `bridge.go` (`ListBridges` + `ReadBridgeState`: **one proplisted `/interface/bridge/port/print`** carries the STP runtime fields on ≥ 7.24 — the first read probes `stp_in_print` — plus one batched `/interface/bridge/monitor =numbers=a,b`; older versions fall back to a batched port monitor, then per-port monitors on active ports only, remembered per device in `BridgeCaps`; roles are normalised from `root-port` etc., `status` is derived from the `forwarding`/`learning` booleans, `designated-bridge-id` replaces the pre-7.19 key, and `tcn_storm` uses Σ per-port `topology-changes` deltas per elapsed minute), a `Runner` seam (`runner.go`: `Run(command, args...)`, `ClientRunner` wraps a pooled client; tests script replies; `IsNoSuchCommand`/`IsPermissionDenied`/`CountOnly` helpers), the **cursored log reader** (`logcursor.go`: `/log/print =.proplist=.id,time,topics,message` with a per-device `.id` cursor and reboot/reset detection; the wireless, bridge and login-line parsers in `logs.go`/`bridge_logs.go`/`logs_login.go` are pure functions over its entries), capability-keyed registration tables (`GetRegistrations(run, menu)` for the wifi/wireless/CAPsMAN menu the capability probe found), ARP/DHCP, and ICMP probes via the API `/ping` command (`RunPing` in `icmp_ping.go` — counted, IPv4/IPv6/hostname, optional `src-address`/`interface` for per-VLAN probing, parses RouterOS duration strings, computes loss/RTT/jitter; distinct from `routeros.Ping`, the TCP liveness dial). Long-running commands — `FetchSpeedTest` (`/tool/fetch` download measurement) and `Traceroute` (`/tool/traceroute`, one pass) — run on **dedicated one-shot connections** (`DialOnce` + `RunCommandWithTimeout`), never on pooled clients, because they exceed the pool's 30s `CommandTimeout` and would hold the per-client mutex
- **`internal/kea/`** — minimal client for the Kea DHCP Control Agent (`lease4-get-all`); used by client discovery to enrich MAC → IP/hostname lookups when `kea_url` is set in app settings
- **`internal/flow/`** — built-in flow collector (`flow.Collector`; `Run` returns at once unless `MIKROTIK_NMS_FLOW_LISTEN` is set). One UDP socket per listen entry → allow-list by **source IP** (`flow_exporters`; a managed device's address is auto-accepted while `flow_auto_accept_devices` is on, everything else is added by an admin; unknown senders are only listed in an LRU ring, never decoded) → per-exporter + global token buckets (`flow_rate_limit_pps`) → a bounded non-blocking queue → **one worker goroutine** that owns all decoder and aggregation state (decode → normalise → aggregate, `recover()` per datagram) → a writer goroutine whose full channel drops the batch (ingest never blocks on SQLite). `flow/decode` is the **only** importer of goflow2 (`github.com/netsampler/goflow2/v2` v2.2.6, decoder packages only) and wraps it in guards (template/field/observation-domain caps, v5/sFlow prechecks, pending data-before-template with TTL, every value copied out of the read buffer), fuzzed by `FuzzDecode`; v9/IPFIX templates persist in `flow_templates` so a restart decodes at once. Normalisation: self-export drop, OPNsense duplicate filter, NAT inside view (RouterOS IPFIX post-NAT dst replaces dst, so WAN downloads show the LAN host), service-port choice (`flow/svcport`, shared with the API for app labels). Aggregation: each flow is split across minutes by overlap; per (exporter, minute) the top `flow_top_n` conversations per `(in_if, out_if)` plus one exact "other" row go to `flow_1m`, and `flow_1m_meta` records every minute the exporter was alive (absence = gap, not zero); a minute flushes at M+3 min, then rolls up hourly into `flow_1h` (+ `flow_1h_meta`). Also: RouterOS ifIndex→name sync every 5 min (`flow_exporter_ifaces`; names from the port-stats collector's interface snapshot via `UseIfaceSource`, the device's own interface print only before its first snapshot, plus the `/interface/vlan` print; learned hints for other exporters; manual names survive), the address plan `flow_prefixes` (internal/vpn/transit from managed devices' addresses, every 15 min; retried after 60 s while a device's uplink rows are still stale after a restart), and **native observation points** (`flow_points`, one per exporter interface with traffic; facing up/down from uplinks/VPN types or the admin-set iface role). `flow/pktgen` builds synthetic datagrams for tests and `cmd/flowreplay`
- **`internal/flowview/`** — pure (no DB/I/O) query side of flows, used by `api/flows*.go`: point direction (`facing` up → download = in_if ∈ set; down → download = out_if ∈ set), row filters (`local_internal`, `exclude_attach`), endpoint classification (multicast → exporter self → `flow_external_prefixes` → `flow_internal_prefixes` → most specific plan prefix → known host in `mac_lookup` → external; RFC 1918 is **not** a blanket rule), grouping (src/dst/pair/conv/app with an exact "other"), **derived-view suggestions** (`Suggest`: gateway-host rule and router-trunk rule for switch ports that cannot export) and the measured Sankey
- **`internal/poller/manager.go`** — orchestrates background polling goroutines:
  - **Per-device cadences** (`poller/cadence.go`, `schedule.go`; design Appendix B): every device-reading loop wakes every 5 s (`pollerTick`), re-reads the device list and runs, per device, only the **tiers** that are due (`devclass.Tier`: counters, ethernet, bridge_ports, bridge_vlan, logs, bridge_hosts, relations, neighbors, routes, arp, dhcp_leases, wifi_registrations, inventory). A tier's interval is `max(devclass.EffectiveInterval(effective class, profile, tier), fleet floor)` — the class cadence (C1 weakest … C3; unprobed = C1; the `light` profile = the C1 plan; a gentler `class_override` wins) **floored** by the setting/env that used to drive the whole loop, so an admin can still slow everything down but never push a device past its class; interval 0 = the read is not in the device's plan (DHCP leases run on C3 only). The next run is the **end** of the last one + interval ±10 % by the device's phase (`devclass.NextRun`/`Phase`; no catch-up — a slow run shifts the next one); a device without a pooled connection is retried after 30 s. `NewCadence(db, cfg)` builds the one `CadenceSource` (`Interval(dev, tier, now)`, `Paused(dev, now)`; settings-backed floors cached 5 s) the manager hands every loop via `UseCadence` (constructors default to the fleet-wide intervals). **Pause** (`polling_paused_until`): only liveness runs (and passive flow intake); every tier's interval is 0, and **nothing ages** — the port-stats snapshot/rates, link staleness, the network-health prunes, `port_hosts` (retention, `FreshPortHosts`), `device_uplinks` (`ListDeviceUplinks` keeps a paused device's rows) and the neighbor sweep all hold a paused device's last read; the counter-delta gap rule stays on the wall clock, so paused minutes are gaps (no rows). Firmware checks, connectivity probes/signal reads, scheduled speed tests, the clients scan, IP auto-follow and the flow ifsync/address plan skip a paused device (logged once per pause). Each loop publishes every tier's next run into `poller.Schedule()`, which `GET /devices/{id}` (and the polling-control responses) return as `polling: {class, profile, paused_until, next_runs: {tier: time}}`; `poller.DevicePaused(db, id, now)` is the predicate for code outside the loops
  - Health (liveness): 30s (env), a lightweight TCP "ping" (`routeros.Ping`, plain dial to the API port — bypasses the connection pool/mutex so it never contends with heavier pollers and doesn't flap on transient API slowness). Owns device `status`: a device is only marked `offline` after it has missed pings for longer than `offline_threshold_seconds` (app_setting, default 120s); within that grace window it reports `unknown` (surfaced as the gray "not responding" state) rather than flapping straight to `offline`. `last_seen` means *last successful contact* (not bumped on failed pings). The frontend renders the status triad — green `online` / red `offline` / gray `unknown`→"not responding" — via the shared helpers in `frontend/src/lib/status.ts`. Liveness runs for every device, paused or not.
  - Info refresh (Tier 6): per device every 60 min (`info_interval` app_setting as the floor), the heavy pass — one **proplisted** `/system/resource/print` (cpu/memory/uptime + version/board/platform/arch + cpu/cpu-count/cpu-frequency), cached in the DB, which also **probes the CPU class** (`poller/classprobe.go`: `devclass.ParseResourceFacts` → `Classify` with the highest frequency ever seen → `SetDeviceClass`). The first classification applies at once; a **change** only when probes at least **24 h apart** agree (every probe in between agreeing; pending candidate in memory), logged once and audited as `device_class_probed`. It no longer prints the interface list: the `interfaces` table is kept by the port-stats Tier 0 read (below). Static details rarely change, so this runs rarely while the liveness ping keeps status fresh; the UI shows the cached values between refreshes. A freshly-added device (empty board/version) is enriched immediately on its first successful ping instead of waiting a full interval, and an online device that is still unclassified is re-probed every 5 min. The info pass never downgrades status — that's the liveness poll's job.
  - Topology: per device `/ip/neighbor` (Tier 3d; C3/C2 2 min, C1 5 min) and the default-route print (3e; C3 60 s, C1/C2 5 min), floored by `MIKROTIK_NMS_TOPOLOGY_INTERVAL` (env, 60 s); once per that env interval it runs the gateway attachment, IP auto-follow (recent sighting = within 2 of the reporting device's neighbor reads) and the topology builder, and broadcasts the graph via WS. **Link staleness** is 3 × the effective neighbor cadence of the device that reported the neighbor (`topology.NeighborAge` = `poller.NeighborAge(cadence)`, used by the loop and `GET /topology` alike; a link no current neighbor row supports is marked down by the build); a paused reporter's rows do not age. Uplinks: one `/ip/route` default-route print per device; interface types and running VPN tunnels come from the port-stats interface snapshot (the `interfaces` table when there is none). Gateway attachment (`kind=gateway-host`) looks the gateway MACs up in `port_hosts` (each online device's latest FDB dump, `ListLatestPortHostsForMACs`) — zero device commands; a gateway no dump holds yet stays unattached until the next dump (`port_hosts_interval`) and the previous rows are kept
  - Traffic: on-demand via `TrafficManager` (`poller/traffic.go`) — every second it vets each `traffic.<id>.<iface>` subscription against the device's class caps (`devclass.LiveCaps`; class = effective class, C1 when unprobed or on the light profile, cached 30 s): **C1 admins only, ≥ 15 s, ≤ 4 interfaces, 1 lease** (a lease = one connection streaming from the device); C2 ≥ 5 s / 8 / 2; C3 ≥ 1 s / 16 / 4; a paused device is refused. It answers with a WS `subscribe.ack` (effective period) or `subscribe.error` (code + message, then drops the subscription) and samples all of a device's granted interfaces in one `monitor-traffic =once=` per period (the traffic page only does this for the port-detail `live` range). `GET /devices/{id}/live-limits` tells the UI the caps and whether it may stream before it subscribes
  - Map link overlay (`poller/livetraffic.go`, `LiveTrafficCollector`): `topology.traffic` (once per counter cycle) and `GET /traffic/links` are derived from the port-stats snapshot — the collector listens in-process (`hub.Listen`) to `traffic.ports` while the map has viewers — so, like `GET /devices/{id}/ports`, they cost the devices **no I/O**. A link is read on its fresher end — per-device read times from `PortStatsCollector.DeviceSampleTimes` (REST) or, for the feed, inferred from which devices' rates changed between published snapshots (a failed read leaves them as they were) — tie: the online one, then the shorter counter cadence, then the A end; never on a bridge. Responses carry `source: "snapshot"`, `sampled_at` (on the port grid: that device's last read), `age_seconds`
  - Port stats (`poller/portstats.go` + `portstats_device.go`, `PortStatsCollector`): owns the **one interface read**. Per online device, concurrently on pooled clients, it runs Tier 0 (`GetInterfaceStats`) every counter interval (C3 15 s, C2 30 s, C1 60 s) and Tier 4a (`GetEthernetStats`) every 5 min; the per-device `tierInterval(dev, tier, now)` hook decides both — the manager's `CadenceSource` (`UseCadence`) with the fleet-wide `port_stats_interval` (default 15s, clamp 5..300, re-read each cycle) as the floor, 0 while paused — each next read counts from the end of the last (± jitter), and every interval-derived rule (delta gap, expiry, flush hold) uses the device's own interval; a paused device's snapshot and rates do not expire (the delta across the pause is still a gap). The Tier 0 rows are the per-device **interface snapshot** (`DeviceSnapshot(id) (rows []routeros.InterfaceSnapshot, at, ok)` — Tier 4a merged by name, served while ≤ 3× the device's interval old; `DeviceIfaces(id)` adds the ethernet read time and `CommandsLastMinute`, the commands this collector sent the device in the last complete minute) that the port monitor, uplinks and flow ifsync read, and they keep the `interfaces` table current (rows upserted when an inventory field changes and all hourly, rows gone from the print pruned in the same transaction; an empty print never wipes a device). It computes rates from counter deltas (resets/gaps > 3× interval skipped), keeps the latest fleet snapshot in memory (served by the API and published on WS `traffic.ports`, subscriber-gated), and writes 1-minute buckets to `port_stats_1m` (each poll interval's bytes are **prorated across the minutes it overlaps**, so 1m charts stay flat at any interval; a flush holds a minute open — at most 1 min — while a device's open interval still credits it, so interleaved per-device cadences attribute exactly; avg = bytes·8/covered seconds, max = peak interval rate; idle minutes not stored) plus an idempotent hourly rollup into `port_stats_1h` (re-rolls every hour since the last rollup, and at startup since the newest hourly bucket, bounded by 23 h — safe because 1m retention is ≥ 1 day). A second loop dumps each online device's bridge FDB (non-local, non-disabled entries; Tier 3b: C3 5 min, C2 10 min, C1 15 min) into `port_hosts`, and its interface stacking (3c: C3 5 min, C2/C1 15 min) — bond members (`/interface/bonding` slaves) and VLAN/PPPoE-client carriers — into `interface_relations`, each floored by `port_hosts_interval` (default 300s, clamp 60..3600), retrying devices without a pooled connection yet (cold start) after 30s; it never writes `mac_lookup`. An FDB row is current for 3 of its device's dump intervals (≥ 15 min; a paused device's against its newest dump): `FreshPortHosts` (used by the gateway attachment; `api/traffic_path.go` still applies the fleet-wide `3 × port_hosts_interval` window). The API derives per-port roles (wan/uplink/downlink/peer/access/wireless/vpn/virtual/idle — `peer` = an up link to another managed device that is not a tree edge, e.g. anchor↔anchor or a redundant/ring link; bond members take their bond's role with `master` set; the physical carrier under a VLAN/PPPoE WAN is an `uplink`), the Internet→port path and an **estimated** Sankey (a tree plus `local:<dev>` "east-west" source nodes so every device conserves flow) from `links` + `device_uplinks` + `port_hosts` + `interface_relations` + these rates via `topology/path.go`. Each device's uplink faces its own default-route egress first, then the first anchor, then the port hearing most devices. A minute/hour with no row fleet-wide is collector downtime: served as a gap (`null` rates) and excluded from averages/p95
  - Flow collector (`internal/flow`, started by the manager, `Flows()` accessor): event-driven by UDP datagrams rather than a poll; its own ticks are the 5 s flush check, a 30 s reconcile (re-reads the `flow_*` settings, exporters, points, device cache; publishes `flows.status` when subscribed), 60 s persisted exporter counters, 5 min ifIndex sync and 15 min address plan (both skip a paused device; its plan rows are carried over). Off unless `MIKROTIK_NMS_FLOW_LISTEN` is set (env, restart required)
  - Firmware: 6h (env, fleet-wide), checks for RouterOS updates; skips paused devices (so does the API's "Check All")
  - WiFi tracking: per controller, the registration tables (Tier 5c: C3 30 s, C2 60 s, C1 5 min) with `wifi_interval` (seconds, re-read each cycle, default 30s) as the floor, drains wireless logs + registration tables and writes `wifi_history` join/leave/roam rows. Each controller's latest registration read stands until its next (expiring after 3 of its reads, never while paused); the absence safety net leaves a client missing from every current read for 10 of its controller's intervals. Log lines come from the manager's shared `LogReader` (`poller/logreader.go`: **one `/log/print` per device per window** whichever consumer asks first, the window being 90 % of the device's `TierLogs` cadence — C3/C2 2 min, C1 5 min — wifi and network-health no longer each dump the log) and registration tables are only read on devices whose `CapabilityCache` (`poller/capabilities.go`: wifi/wireless/caps-man/dhcp-server/bridge probed with `=count-only=` at session start and every 24 h; a permission trap is `CapPermissionMissing`, never "absent") shows a wifi role — switches never get the trapping registration prints. `poller/login_watch.go` parses the `system,info,account` login lines and confirms unexpected API logins with one `/user/active` read → `device_findings` kind `parallel_api_poller` (the NMS's own addresses come from the `nms_source_addresses` setting plus the outbound address)
  - Client discovery: per device ARP (Tier 5a: C3 5 min, C2/C1 30 min) and DHCP leases (5b: C3 only) floored by the `client_discovery_interval` setting (seconds, re-read each cycle, default 15m), plus the optional Kea/OPNsense leases once per that interval; refreshes `mac_lookup` and `client_history`
  - Network health: per device bridges + bridge ports (Tier 2a–2c, via `routeros.ReadBridgeState` — 2 commands per device on ≥ 7.24 instead of one monitor per port; C3/C2 2 min, C1 5 min) + the bridge VLAN table (3a, `/interface/bridge/vlan`; C3/C2 5 min, C1 15 min) + bridge logs (TierLogs, from the shared `LogReader`), floored by `MIKROTIK_NMS_NETWORK_HEALTH_INTERVAL` (env, 60s), + per-device interface runtime state (running/disabled/last-link-up/last-link-down) read from the port-stats interface snapshot every max(floor, counter cadence) (`UseInterfaceSnapshots` — no interface or ethernet print of its own; a device without a fresh snapshot is skipped). Once per floor interval it prunes the bridge / port / VLAN / interface-state rows older than 3 × the device's cadence for them (never a paused device's) and publishes the `network.health` summary. Writes `bridge_status` / `bridge_port_status` / `bridge_vlans` / `interface_state` / `loop_events`. The **VLANs** page renders a VLAN×device matrix (tagged/untagged per device) from `bridge_vlans`, with admin-editable per-VLAN labels in `vlan_labels`. Port-monitoring half is runtime-tunable via `port_monitor_enabled` / `port_monitor_filter` / `port_flap_threshold` / `port_flap_window_seconds` settings; emits `port_disabled` / `port_link_down` / `port_link_flap` / `port_loop_protect` event kinds. Flaps are **`link-downs` deltas** between consecutive snapshots (a counter reset counts 0; the running-transition heuristic only stands in while there is no counter baseline, e.g. right after a restart), `port_flap_threshold` of them within the window fire one `port_link_flap`; loop-protect state comes from the Tier 4a merge (up to 5 min old).
  - Connectivity: default 30s (fleet-wide), runtime-tunable via `connectivity_interval` / `connectivity_ping_count` settings; a target whose probing device is paused is skipped without a sample. Probes `ping_targets` with the API `/ping` command — kind `internet` pings a fixed address (IPv4/IPv6/hostname, optional `src_address`/`src_interface` for per-VLAN/ISP-path probing) from a chosen device; kind `client` (a "watch") resolves the MAC's current IP from `mac_lookup` each cycle and probes from the device that sees the client (override via `device_id`). Writes `ping_samples` (loss/RTT/jitter; rows with non-empty `error` mean the probe couldn't run) and `client_signal_samples` for wireless watches, broadcasts each sample on WS `connectivity.sample`. Probes are grouped per device and run concurrently across devices (serialized per device by the client mutex). When an internet sample's loss ≥ `traceroute_loss_threshold` (setting, 0 = off), it auto-captures a traceroute (dedicated connection, per-target 10min cooldown, global concurrency cap) into `traceroute_runs` and broadcasts `connectivity.traceroute` — traceroutes can also be run on demand per target.
  - Speed tests: default 6h (fleet-wide), runtime-tunable via `speedtest_interval` (seconds, clamp 300..604800, ~10min startup delay so deploys don't trigger download bursts). Runs `speed_tests` rows sequentially (scheduled runs skip a paused device without a sample; run-now does not): dedicated connection to the device, `/tool/fetch url=… output=none` timed download (120s cap), Mbps into `speed_samples`, broadcast on WS `connectivity.speed`. An optional `src_address` sources the fetch from a specific device IP for per-VLAN measurement — fetch's only source selector (`/tool/fetch` has **no interface/vrf parameter**; verified on RouterOS 7.23). The UI's source picker is fed by `GET /devices/{id}/addresses` (`routeros.ListAddresses`: live `/ip/address` + `/ipv6/address` joined with `/interface/vlan` for VLAN ids; pooled client, online devices only). Run-now via the API is async (202) and shares the same code path.
  - Retention: 1h, deletes old traffic samples, stale neighbors (per device: unseen for 24 h, or 3 of its neighbor reads if longer; never a paused device's), old wifi/client/loop history, old ping/signal/speed samples and traceroute runs, and port stats / port hosts per `port_stats_1m_days` (default 2 — the UI reads ≤ 24h of 1m data; min 1), `port_stats_1h_days` (365) and `port_hosts_stale_days` (7; a paused device's rows are kept); port-stats deletes run in bounded chunks so lowering a retention never holds the SQLite write lock for long. The admin history purge's `traffic` target also clears `port_stats_1m` / `port_stats_1h`. Flows via `flow.Sweep`: `flow_1m` (+meta) per `flow_1m_days` (default 3), `flow_1h` (+meta) per `flow_1h_days` (default 90), orphan rows of deleted exporters in chunks, `flow_templates` older than 7 d, learned interfaces unseen for 30 d, auto native points unseen for 7 d; the purge's `flows` target clears the flow fact tables
- **`internal/poller/firmware.go`** — `UpgradeExecutor` runs async firmware upgrade jobs with per-device progress tracking (download → install → reboot → verify), broadcasting status via WS `upgrade.progress.<jobId>`
- **`internal/topology/builder.go`** — builds deduplicated bidirectional link graph from raw neighbor data. Resolution priority: MAC → IP → identity. Canonical link ordering `(min_id, max_id)` prevents duplicates.
- **`internal/topology/path.go`** — pure role graph for traffic analytics (`BuildRoleGraph`): infers the physical tree from MNDP links + bridge FDB by nearest-ancestor inference (a BFS would collapse the flat-L2 MNDP near-mesh into a star), anchored on egress data (`device_uplinks`); assigns per-port roles, `Path` (Internet → device/port hops with segment rates) and `Sankey` (estimated single-direction flow forest, acyclic by construction). The API loads its inputs from the DB and caches the graph for 30s (`api/traffic_path.go`)
- **`internal/ws/`** — topic-based WebSocket pub/sub hub. Topics: `device.health`, `topology.update`, `topology.traffic`, `traffic.<id>.<iface>`, `traffic.ports`, `firmware.update`, `upgrade.progress.<jobId>`, `wifi.event`, `network.health`, `network.health.event`, `connectivity.sample`, `connectivity.speed`, `connectivity.traceroute`, `flows.flushed` (after each flushed minute), `flows.status` (collector status every 30 s) — both subscriber-gated. A client's subscribe/unsubscribe/disconnect go through one ordered op channel; `ws.Client` carries the user (`ClientInfo`, role) so a topic owner can vet subscribers and answer with per-client control frames (`Hub.Notify`: `subscribe.ack` / `subscribe.error`, the only frames with a `type`); `Hub.Listen` adds an in-process listener that counts as a subscriber
- **`internal/api/`** — chi router, REST endpoints under `/api/v1/`, WebSocket at `/api/v1/ws`. Flow endpoints (`api/flows*.go`): `/flows/{status,setup,points,points/suggestions,top,port,coverage}` and `/flows/exporters/{id}/interfaces` are readable by **every logged-in user** (per-host detail like `/clients`); exporter, interface and point writes are admin-only and call `Collector.Reload()`; `/traffic/sankey?source=flows&point=` serves the measured Sankey (the Phase 1 response carries `"source":"counters"`)

### Key patterns

- shadcn/ui in this project uses **base-ui** (not Radix). Use `render={<Component />}` instead of `asChild` for composition.
- Frontend API/WS base is **same-origin by default** (the reverse proxy serves `/api/*`); `NEXT_PUBLIC_API_URL`/`NEXT_PUBLIC_WS_URL` are optional build-time overrides for split-origin deployments only — leave them empty otherwise (a stale baked URL breaks every page with "Failed to fetch"). `next dev` on port 3000 auto-targets `<hostname>:8080`. Network-level fetch failures surface as `ApiError(0, …)` naming the resolved target.
- Device credentials in `devices.password_enc` are encrypted at rest (AES-256-GCM, `internal/crypto`) when `MIKROTIK_NMS_ENCRYPTION_KEY` is set — encrypt/decrypt happens transparently in `queries` (CreateDevice/UpdateDevice/GetDevice/ListDevices), plaintext rows migrate on startup, and the column carries an `enc:v1:` prefix. Without a key it falls back to plaintext and is redacted from `/admin` backups/exports.
- Topology links are **derived** from raw neighbor data in the `neighbors` table, stored in `links` table. Rebuilt on each topology poll cycle.
- Traffic analytics is always-on and cheap: one `/interface/print` per device per `port_stats_interval` (not a `monitor-traffic` stream per port). The per-interface `monitor-traffic` stream is on-demand and class-capped: it starts once a `traffic.<id>.<iface>` subscription is granted (1 s on C3, 15 s and admin-only on C1). Every other live view (map links, port grid, `/traffic/ports/*`) reads the snapshot; tests prove a read path device-free by dialling the pool to `routeros/routerostest` (a fake API endpoint that records every command after login). Port endpoints take `device`/`iface` as query params (`/traffic/ports/history?device=&iface=`) because interface names can contain spaces/slashes. Direction: `rx` = into the device through the port, `tx` = out of it; download is `rx` on wan/uplink/vpn ports and `tx` on downlink/access/wireless ports; peer/virtual/idle ports show raw in/out.
- Flows are **measured per exporter and never summed across exporters** (the same packet is often seen by a firewall and a router, or both ends of a trunk); every view is one observation point = one exporter + a set of its ifIndexes. Native points are created by the collector; **derived** points represent ports of switches that cannot export (hardware-offloaded forwarding) from a neighbouring exporter and are added by admins from `flowview.Suggest`; coverage = flow bytes / Phase 1 port-counter bytes over the buckets both cover. Flow fact tables (`flow_1m`, `flow_1h`, `*_meta`) use **INTEGER unix-second buckets** and **BLOB IPs** (4 bytes IPv4, 16 bytes IPv6, v4-mapped unmapped first; the folded "other" row is the empty blob `x''` — bind `[]byte{}`, never `nil`), have no FKs for size, and `flow_exporters`/`flow_points` ids are `AUTOINCREMENT` so a deleted exporter's orphan rows (swept later) never attach to a new one. ifIndex 0 = router-local, never a row or point member.
- WiFi join/leave/roam events have two sources: **wireless log lines** (authoritative — parsed from `/log/print`) and **registration-table snapshots** (safety net). Each row in `wifi_history` records its `source` (`log` / `snapshot` / `absence`) so the UI can show provenance.
- Bridge log parsing is best-effort: regex patterns in `routeros/bridge_logs.go` look for "loop detected" / "MAC flap" / "BPDU on edge". Patterns are deliberately loose; new RouterOS versions may emit phrasing that needs regex updates.
- App settings (`app_settings` table) are runtime-tunable via the **Settings** page; backend pollers that read from this table (wifi_interval, client_discovery_interval, connectivity_interval, connectivity_ping_count, speedtest_interval, traceroute_loss_threshold, kea_url, DNS servers, port_monitor_*, offline_threshold_seconds, info_interval, tcn_storm_threshold, port_stats_interval, port_hosts_interval, port_stats_1m_days, port_stats_1h_days, port_hosts_stale_days, and the flow collector's flow_top_n, flow_top_n_hourly, flow_max_rows_per_minute, flow_1m_days, flow_1h_days, flow_rate_limit_pps, flow_auto_accept_devices, flow_internal_prefixes, flow_external_prefixes, flow_resolve_ptr, flow_advertise_address — re-read on its 30 s reconcile or per request) pick up changes on the next cycle without a restart. Pollers driven by env vars (health, topology, firmware, network_health, retention) and the flow collector's `MIKROTIK_NMS_FLOW_LISTEN` require a backend restart. The per-device read intervals among them (`port_stats_interval`, `port_hosts_interval`, `wifi_interval`, `client_discovery_interval`, `info_interval`, `MIKROTIK_NMS_TOPOLOGY_INTERVAL`, `MIKROTIK_NMS_NETWORK_HEALTH_INTERVAL`) are **floors**: each device runs its class cadence when that is slower (see Per-device cadences).
- Continuous deploy to the LXC has two complementary paths: a **HMAC webhook agent** (`backend/cmd/deploy-agent` + `deploy/webhook-agent/`) and a **self-hosted GitHub Actions runner** (`deploy/lxc/runner-install.sh` + `.github/workflows/deploy-lxc.yml`). Both call `install.sh --skip-deps`; the runner path is gated by a narrow sudoers grant to `/usr/local/sbin/mikrotik-nms-deploy` (a wrapper that validates the workspace before forwarding to the installer).
- **Device I/O fence** (`routeros/policy.go`): `main` installs `routeros.SetDialPolicy` from the config before anything runs; `Pool.Dial`, `DialOnce`, `Ping`, `ScanSubnet` and `ScanMNDP` all call `CheckTarget`/`PollingAllowed`, so **new code that reaches a device must go through them, never `net.Dial` or the go-routeros dialers directly**. With `MIKROTIK_NMS_POLLERS=off` the manager starts only the DB-only jobs (retention, port-stats startup rollup) and the flow collector never binds; on-demand API actions map `ErrPollersOff` → `503` and `ErrTargetNotAllowed` → `403` via `writeDialPolicyError`. `/health` reports `pollers` (the UI banner), the authenticated `/system` adds `allowed_target_cidrs`. `install.sh` writes `local` + the LXC's own subnets (`--target-cidrs` overrides) and appends them once to existing env files.
- First-run: `POST /api/v1/auth/setup` creates the initial admin user (only works when 0 users exist).
- The flow collector is **off everywhere unless configured**: code default `""`, `install.sh` writes `# MIKROTIK_NMS_FLOW_LISTEN=:2055` commented (new env files, and appended once to existing ones), Compose/K8s/`.env.example` ship it commented or empty, and the K8s UDP Service lives in `deploy/k8s/optional/` so `kubectl apply -f deploy/k8s/` never creates it. Device-side setup (RouterOS IPFIX, OPNsense NetFlow v9, derived views) is documented in `docs/FLOW-EXPORT.md`.
