# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

**MikroTik NMS** — a web-based network management tool for MikroTik RouterOS devices. Provides network topology visualization, real-time traffic monitoring, device health overview, and mass firmware management. Read-only monitoring with WinBox deep linking (`winbox://`) for device configuration. Full user management with admin/viewer roles.

## Build / Test / Lint Commands

- **Build all:** `make build` (outputs `bin/mikrotik-nms` + frontend `.next`)
- **Build backend only:** `make build-backend` or `cd backend && go build ./cmd/mikrotik-nms/`
- **Build frontend only:** `make build-frontend` or `cd frontend && npm run build`
- **Run backend (dev):** `make dev-backend` (requires `MIKROTIK_NMS_JWT_SECRET` env var)
- **Run frontend (dev):** `make dev-frontend`
- **Test:** `make test` or `cd backend && go test ./...`
- **Test single package:** `cd backend && go test -v ./internal/topology/ -run TestBuildLinks`
- **Lint:** `make lint` (runs `go vet` + `npm run lint`)
- **Docker:** `docker compose build` then `docker compose up -d`
- **K8s:** `kubectl apply -f deploy/k8s/` (edit `secret.yaml` and `ingress.yaml` first)
- **Dev (both):** `./scripts/dev.sh` starts backend + frontend concurrently

## Architecture

Monorepo with Go backend + Next.js frontend communicating via REST API and WebSocket.

### Backend (`backend/`)

Go with `chi` router, SQLite (WAL mode) via `modernc.org/sqlite`, no ORM (raw SQL in `internal/database/queries/`).

- **`cmd/mikrotik-nms/main.go`** — entrypoint, wires config → DB → WebSocket hub → poller manager → HTTP server
- **`internal/config/`** — env-based configuration (`MIKROTIK_NMS_*` prefix)
- **`internal/database/`** — SQLite setup, goose migrations (`001_init.sql` … `021_interface_relations.sql`), query functions. Tables: `users`, `devices`, `interfaces`, `neighbors`, `links`, `traffic_samples`, `firmware_status`, `upgrade_jobs`, `upgrade_job_devices`, `dns_servers`, `wifi_history`, `client_history`, `mac_lookup`, `app_settings`, `bridge_status`, `bridge_port_status`, `loop_events`, `interface_state`, `bridge_vlans`, `vlan_labels`, `password_reset_tokens`, `ping_targets`, `ping_samples`, `client_signal_samples`, `speed_tests`, `speed_samples`, `traceroute_runs`, `device_uplinks`, `port_stats_1m`, `port_stats_1h`, `port_hosts`, `interface_relations`
- **`internal/auth/`** — JWT (access 15min + refresh 7d), bcrypt passwords, chi middleware (`RequireAuth`, `RequireRole`)
- **`internal/routeros/`** — RouterOS API client pool wrapping `go-routeros/routeros/v3`. Functions for `/system/resource`, `/ip/neighbor`, `/interface/monitor-traffic`, `/interface/print` byte/packet counters (`GetInterfaceStats`), the bridge FDB (`GetBridgeHosts`: `/interface/bridge/host` `local=false`), `/system/package/update`, `/interface/bridge` + `monitor`, `/interface/bridge/port` + `monitor`, CAPsMAN/wifi registration tables, ARP/DHCP, parsed `/log/print` events (wireless and bridge topics), and ICMP probes via the API `/ping` command (`RunPing` in `icmp_ping.go` — counted, IPv4/IPv6/hostname, optional `src-address`/`interface` for per-VLAN probing, parses RouterOS duration strings, computes loss/RTT/jitter; distinct from `routeros.Ping`, the TCP liveness dial). Long-running commands — `FetchSpeedTest` (`/tool/fetch` download measurement) and `Traceroute` (`/tool/traceroute`, one pass) — run on **dedicated one-shot connections** (`DialOnce` + `RunCommandWithTimeout`), never on pooled clients, because they exceed the pool's 30s `CommandTimeout` and would hold the per-client mutex
- **`internal/kea/`** — minimal client for the Kea DHCP Control Agent (`lease4-get-all`); used by client discovery to enrich MAC → IP/hostname lookups when `kea_url` is set in app settings
- **`internal/poller/manager.go`** — orchestrates background polling goroutines:
  - Health (liveness): 30s (env), a lightweight TCP "ping" (`routeros.Ping`, plain dial to the API port — bypasses the connection pool/mutex so it never contends with heavier pollers and doesn't flap on transient API slowness). Owns device `status`: a device is only marked `offline` after it has missed pings for longer than `offline_threshold_seconds` (app_setting, default 120s); within that grace window it reports `unknown` (surfaced as the gray "not responding" state) rather than flapping straight to `offline`. `last_seen` means *last successful contact* (not bumped on failed pings). The frontend renders the status triad — green `online` / red `offline` / gray `unknown`→"not responding" — via the shared helpers in `frontend/src/lib/status.ts`.
  - Info refresh: `info_interval` (app_setting, default 60m), the heavy pass — full `/system/resource` (cpu/memory/uptime + version/board/platform/arch) and the interface list, cached in the DB (rows for interfaces no longer on the device are pruned after each full print). Static details rarely change, so this runs rarely while the liveness ping keeps status fresh; the UI shows the cached values between refreshes. A freshly-added device (empty board/version) is enriched immediately on its first successful ping instead of waiting a full interval. The info pass never downgrades status — that's the liveness poll's job.
  - Topology: 60s (env), polls `/ip/neighbor`, runs topology builder, broadcasts graph via WS
  - Traffic: on-demand via `TrafficManager` — starts/stops per-interface 1s polling when WS clients subscribe to a `traffic.<id>.<iface>` topic (the traffic page only does this for the port-detail `live` range)
  - Port stats (`poller/portstats.go`, `PortStatsCollector`): every `port_stats_interval` (default 15s, clamp 5..300, re-read each cycle) polls `/interface/print` counters for ALL interfaces of every online device concurrently on pooled clients, computes rates from counter deltas (resets/gaps > 3× interval skipped), keeps the latest fleet snapshot in memory (served by the API and published on WS `traffic.ports`, subscriber-gated), and writes 1-minute buckets to `port_stats_1m` (each poll interval's bytes are **prorated across the minutes it overlaps**, so 1m charts stay flat at any interval; avg = bytes·8/covered seconds, max = peak interval rate; idle minutes not stored) plus an idempotent hourly rollup into `port_stats_1h` (re-rolls every hour since the last rollup, and at startup since the newest hourly bucket, bounded by 23 h — safe because 1m retention is ≥ 1 day). A second loop dumps each online device's bridge FDB (non-local, non-disabled entries) into `port_hosts`, and its interface stacking — bond members (`/interface/bonding` slaves) and VLAN/PPPoE-client carriers — into `interface_relations`, every `port_hosts_interval` (default 300s, clamp 60..3600), retrying devices without a pooled connection yet (cold start) every 30s within the interval; it never writes `mac_lookup`. The API derives per-port roles (wan/uplink/downlink/peer/access/wireless/vpn/virtual/idle — `peer` = an up link to another managed device that is not a tree edge, e.g. anchor↔anchor or a redundant/ring link; bond members take their bond's role with `master` set; the physical carrier under a VLAN/PPPoE WAN is an `uplink`), the Internet→port path and an **estimated** Sankey (a tree plus `local:<dev>` "east-west" source nodes so every device conserves flow) from `links` + `device_uplinks` + `port_hosts` + `interface_relations` + these rates via `topology/path.go`. Each device's uplink faces its own default-route egress first, then the first anchor, then the port hearing most devices. A minute/hour with no row fleet-wide is collector downtime: served as a gap (`null` rates) and excluded from averages/p95
  - Firmware: 6h (env), checks for RouterOS updates
  - WiFi tracking: default 30s, runtime-tunable via the `wifi_interval` setting (seconds, re-read each cycle), drains wireless logs + registration tables and writes `wifi_history` join/leave/roam rows
  - Client discovery: default 15m, runtime-tunable via the `client_discovery_interval` setting (seconds, re-read each cycle), pulls ARP/DHCP/CAPsMAN + optional Kea leases, refreshes `mac_lookup` and `client_history`
  - Network health: 60s (env), polls bridges + bridge ports + the bridge VLAN table (`/interface/bridge/vlan`) + bridge logs + per-device interface runtime state (running/disabled/last-link-up/last-link-down). Writes `bridge_status` / `bridge_port_status` / `bridge_vlans` / `interface_state` / `loop_events`. The **VLANs** page renders a VLAN×device matrix (tagged/untagged per device) from `bridge_vlans`, with admin-editable per-VLAN labels in `vlan_labels`. Port-monitoring half is runtime-tunable via `port_monitor_enabled` / `port_monitor_filter` / `port_flap_threshold` / `port_flap_window_seconds` settings; emits `port_disabled` / `port_link_down` / `port_link_flap` event kinds.
  - Connectivity: default 30s, runtime-tunable via `connectivity_interval` / `connectivity_ping_count` settings. Probes `ping_targets` with the API `/ping` command — kind `internet` pings a fixed address (IPv4/IPv6/hostname, optional `src_address`/`src_interface` for per-VLAN/ISP-path probing) from a chosen device; kind `client` (a "watch") resolves the MAC's current IP from `mac_lookup` each cycle and probes from the device that sees the client (override via `device_id`). Writes `ping_samples` (loss/RTT/jitter; rows with non-empty `error` mean the probe couldn't run) and `client_signal_samples` for wireless watches, broadcasts each sample on WS `connectivity.sample`. Probes are grouped per device and run concurrently across devices (serialized per device by the client mutex). When an internet sample's loss ≥ `traceroute_loss_threshold` (setting, 0 = off), it auto-captures a traceroute (dedicated connection, per-target 10min cooldown, global concurrency cap) into `traceroute_runs` and broadcasts `connectivity.traceroute` — traceroutes can also be run on demand per target.
  - Speed tests: default 6h, runtime-tunable via `speedtest_interval` (seconds, clamp 300..604800, ~10min startup delay so deploys don't trigger download bursts). Runs `speed_tests` rows sequentially: dedicated connection to the device, `/tool/fetch url=… output=none` timed download (120s cap), Mbps into `speed_samples`, broadcast on WS `connectivity.speed`. An optional `src_address` sources the fetch from a specific device IP for per-VLAN measurement — fetch's only source selector (`/tool/fetch` has **no interface/vrf parameter**; verified on RouterOS 7.23). The UI's source picker is fed by `GET /devices/{id}/addresses` (`routeros.ListAddresses`: live `/ip/address` + `/ipv6/address` joined with `/interface/vlan` for VLAN ids; pooled client, online devices only). Run-now via the API is async (202) and shares the same code path.
  - Retention: 1h, deletes old traffic samples, stale neighbors, old wifi/client/loop history, old ping/signal/speed samples and traceroute runs, and port stats / port hosts per `port_stats_1m_days` (default 2 — the UI reads ≤ 24h of 1m data; min 1), `port_stats_1h_days` (365) and `port_hosts_stale_days` (7); port-stats deletes run in bounded chunks so lowering a retention never holds the SQLite write lock for long. The admin history purge's `traffic` target also clears `port_stats_1m` / `port_stats_1h`
- **`internal/poller/firmware.go`** — `UpgradeExecutor` runs async firmware upgrade jobs with per-device progress tracking (download → install → reboot → verify), broadcasting status via WS `upgrade.progress.<jobId>`
- **`internal/topology/builder.go`** — builds deduplicated bidirectional link graph from raw neighbor data. Resolution priority: MAC → IP → identity. Canonical link ordering `(min_id, max_id)` prevents duplicates.
- **`internal/topology/path.go`** — pure role graph for traffic analytics (`BuildRoleGraph`): infers the physical tree from MNDP links + bridge FDB by nearest-ancestor inference (a BFS would collapse the flat-L2 MNDP near-mesh into a star), anchored on egress data (`device_uplinks`); assigns per-port roles, `Path` (Internet → device/port hops with segment rates) and `Sankey` (estimated single-direction flow forest, acyclic by construction). The API loads its inputs from the DB and caches the graph for 30s (`api/traffic_path.go`)
- **`internal/ws/`** — topic-based WebSocket pub/sub hub. Topics: `device.health`, `topology.update`, `topology.traffic`, `traffic.<id>.<iface>`, `traffic.ports`, `firmware.update`, `upgrade.progress.<jobId>`, `wifi.event`, `network.health`, `network.health.event`, `connectivity.sample`, `connectivity.speed`, `connectivity.traceroute`
- **`internal/api/`** — chi router, REST endpoints under `/api/v1/`, WebSocket at `/api/v1/ws`

### Frontend (`frontend/`)

Next.js 16 (App Router) + React 19 + shadcn/ui (base-ui, not Radix) + Tailwind CSS v4.

- **Route group `(authenticated)/`** — protected layout with sidebar, redirects to `/login` if no token
- **Pages:** dashboard, topology (node card-grid view built from neighbor data; the `cytoscape` deps in package.json are currently unused), devices (data table + CRUD), device detail (`/devices/[id]` — tabs for interfaces/neighbors, CPU/mem gauges), traffic (fleet-wide port analytics with URL-addressable drill-down — `?view=top|devices|flows&device=&iface=&range=`: top talkers ranked by avg/peak/bytes with sparklines, per-device port heatmap + ranked ports, port detail with Internet→port path strip, history chart + avg/peak/p95/volume stats and a behind-this-port panel (FDB clients, VLANs), and a Flows tab with an **estimated** Sankey from port counters + topology; ranges live|15m|1h|6h|24h|7d|30d; live via WS `traffic.ports`), firmware (bulk upgrade with real-time progress via WS), wifi (per-AP client list + roam timeline + live event feed), clients (ARP/DHCP/CAPsMAN snapshot enriched with `mac_lookup`), connectivity (internet ping targets — IPv4/IPv6/hostname, optional per-VLAN source — + per-client watches: latency/loss/jitter charts, wireless signal history, a correlated event timeline of wifi roams + port events for root-causing dropoffs, on-demand/auto-captured traceroutes, and scheduled router-side download speed tests; live via WS `connectivity.*`), network-health (bridge/STP state + per-port state + recent loop/flap/port events), vlans (VLAN×device tagged/untagged matrix + per-VLAN port detail + admin-editable VLAN labels), users (admin), settings (admin: polling intervals, retention, dark mode, Kea Control Agent URL, DNS servers, port-monitoring filter/thresholds, traffic analytics intervals/retention)
- **`src/lib/api.ts`** — typed API client for all REST endpoints
- **`src/lib/ws.ts`** — WebSocket client with auto-reconnect and topic subscription
- **`src/context/auth.tsx`** — auth state management (login, setup, refresh, logout)
- **`src/hooks/use-websocket.ts`** — React hook for subscribing to WS topics with shared connection

### Key patterns

- shadcn/ui in this project uses **base-ui** (not Radix). Use `render={<Component />}` instead of `asChild` for composition.
- Frontend API/WS base is **same-origin by default** (the reverse proxy serves `/api/*`); `NEXT_PUBLIC_API_URL`/`NEXT_PUBLIC_WS_URL` are optional build-time overrides for split-origin deployments only — leave them empty otherwise (a stale baked URL breaks every page with "Failed to fetch"). `next dev` on port 3000 auto-targets `<hostname>:8080`. Network-level fetch failures surface as `ApiError(0, …)` naming the resolved target.
- Device credentials in `devices.password_enc` are encrypted at rest (AES-256-GCM, `internal/crypto`) when `MIKROTIK_NMS_ENCRYPTION_KEY` is set — encrypt/decrypt happens transparently in `queries` (CreateDevice/UpdateDevice/GetDevice/ListDevices), plaintext rows migrate on startup, and the column carries an `enc:v1:` prefix. Without a key it falls back to plaintext and is redacted from `/admin` backups/exports.
- Topology links are **derived** from raw neighbor data in the `neighbors` table, stored in `links` table. Rebuilt on each topology poll cycle.
- Traffic analytics is always-on and cheap: one `/interface/print` per device per `port_stats_interval` (not a `monitor-traffic` stream per port). The 1s per-interface stream is on-demand: it starts when a WebSocket client subscribes to `traffic.<id>.<iface>`. Port endpoints take `device`/`iface` as query params (`/traffic/ports/history?device=&iface=`) because interface names can contain spaces/slashes. Direction: `rx` = into the device through the port, `tx` = out of it; download is `rx` on wan/uplink/vpn ports and `tx` on downlink/access/wireless ports; peer/virtual/idle ports show raw in/out.
- WiFi join/leave/roam events have two sources: **wireless log lines** (authoritative — parsed from `/log/print`) and **registration-table snapshots** (safety net). Each row in `wifi_history` records its `source` (`log` / `snapshot` / `absence`) so the UI can show provenance.
- Bridge log parsing is best-effort: regex patterns in `routeros/bridge_logs.go` look for "loop detected" / "MAC flap" / "BPDU on edge". Patterns are deliberately loose; new RouterOS versions may emit phrasing that needs regex updates.
- App settings (`app_settings` table) are runtime-tunable via the **Settings** page; backend pollers that read from this table (wifi_interval, client_discovery_interval, connectivity_interval, connectivity_ping_count, speedtest_interval, traceroute_loss_threshold, kea_url, DNS servers, port_monitor_*, offline_threshold_seconds, info_interval, tcn_storm_threshold, port_stats_interval, port_hosts_interval, port_stats_1m_days, port_stats_1h_days, port_hosts_stale_days) pick up changes on the next cycle without a restart. Pollers driven by env vars (health, topology, firmware, network_health, retention) require a backend restart.
- Continuous deploy to the LXC has two complementary paths: a **HMAC webhook agent** (`backend/cmd/deploy-agent` + `deploy/webhook-agent/`) and a **self-hosted GitHub Actions runner** (`deploy/lxc/runner-install.sh` + `.github/workflows/deploy-lxc.yml`). Both call `install.sh --skip-deps`; the runner path is gated by a narrow sudoers grant to `/usr/local/sbin/mikrotik-nms-deploy` (a wrapper that validates the workspace before forwarding to the installer).
- First-run: `POST /api/v1/auth/setup` creates the initial admin user (only works when 0 users exist).
