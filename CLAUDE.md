# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

**MikroTik NMS** — a web-based network management tool for MikroTik RouterOS devices. Provides network topology visualization, real-time traffic monitoring, device health overview, and mass firmware management. Read-only monitoring with WinBox deep linking (`winbox://`) for device configuration. Full user management with admin/viewer roles.

## Build / Test / Lint Commands

- **Build all:** `make build` (outputs `bin/mikrotik-nms` + frontend `.next`)
- **Build backend only:** `make build-backend` or `cd backend && go build ./cmd/mikrotik-nms/`
- **Build frontend only:** `make build-frontend` or `cd frontend && npm run build`
- **Run backend (dev):** `make dev-backend` (requires `MIKROTIK_NMS_JWT_SECRET` env var; polls **nothing** — `MIKROTIK_NMS_POLLERS` defaults to `off`). To poll real lab devices: `MIKROTIK_NMS_ALLOWED_TARGET_CIDRS=<cidr,…> make dev-backend-poll`
- **Run frontend (dev):** `make dev-frontend`
- **Test:** `make test` or `cd backend && go test ./...`
- **Test single package:** `cd backend && go test -v ./internal/topology/ -run TestBuildLinks`
- **Lint:** `make lint` (runs `go vet` + `npm run lint`)
- **Docker:** `docker compose build` then `docker compose up -d`
- **K8s:** `kubectl apply -f deploy/k8s/` (edit `secret.yaml`, `ingress.yaml` and the `MIKROTIK_NMS_ALLOWED_TARGET_CIDRS` in `configmap.yaml` first — the backend refuses to start with polling on and an empty allow-list)
- **Dev (both):** `./scripts/dev.sh` starts backend + frontend concurrently
- **Fuzz the flow decoder:** `make fuzz-flow` (60 s of `FuzzDecode`; the seed corpus also runs in plain `go test`)
- **Fuzz the RouterOS reply reader:** `make fuzz-ros` (60 s of `FuzzSentence` in `internal/routeros`; its seeds also run in plain `go test`). `make test` and CI also run the vendored library's own tests (`cd backend/third_party/go-routeros && go test ./...`)
- **Replay synthetic flows (dev):** `cd backend && go run ./cmd/flowreplay -to 127.0.0.1:2055 -scenario lab` — RouterOS IPFIX from 127.0.0.2 + OPNsense NetFlow v9 from 127.0.0.3 (+ an unknown sender 127.0.0.4) with current timestamps; the backend needs `MIKROTIK_NMS_FLOW_LISTEN` and exporters for those addresses (`-mix` adds a multi-host mix of lab hosts talking to common internet services, `-skip-templates` tests persisted templates, `-dir` replays `MIKROTIK_NMS_FLOW_CAPTURE_DIR` captures)

## Architecture

Monorepo with Go backend + Next.js frontend communicating via REST API and WebSocket.

### Backend (`backend/`)

Go with `chi` router, SQLite (WAL mode) via `modernc.org/sqlite`, no ORM (raw SQL in `internal/database/queries/`).

- **`cmd/mikrotik-nms/main.go`** — entrypoint, wires config → DB → WebSocket hub → poller manager → HTTP server
- **`internal/config/`** — env-based configuration (`MIKROTIK_NMS_*` prefix), incl. the polling fence — `Pollers` (`MIKROTIK_NMS_POLLERS`: `local`|`off`, **code default `off` = no device or UDP I/O**) and `AllowedTargetCIDRs` (`MIKROTIK_NMS_ALLOWED_TARGET_CIDRS`: parsed `netip.Prefix` allow-list, **required with `local`**, invalid entries are startup errors) — `FlowListen` (`MIKROTIK_NMS_FLOW_LISTEN`: comma-separated UDP bind addresses, invalid entries logged + skipped, **empty = flow collector off**) and the dev-only `FlowCaptureDir`
- **`internal/database/`** — SQLite setup, goose migrations (`001_init.sql` … `032_alert_notified_severity.sql`; **strictly additive from 023 on** — the previous release's binary must run on the new schema, so new tables and nullable columns only, never drop/rename/re-key within a milestone), query functions. Tables: `users`, `devices` (incl. the P0-4 columns `device_class`/`class_override`/`class_probed_at`/`poll_profile`/`polling_paused_until`/`cpu_count`/`cpu_mhz_max`, and `pin_cert_sha256` — the certificate fingerprint an API-TLS device is pinned to), `audit_log` (admin actions: pauses, profile and class-override changes, address-move decisions, firmware requests), `device_findings` (per-device hygiene findings such as `parallel_api_poller`, upserted by kind+detail), `alerts` / `alert_silences` / `notification_channels` (INTEGER unix-second times), `interfaces`, `neighbors`, `links`, `traffic_samples`, `firmware_status`, `firmware_releases`, `upgrade_jobs`, `upgrade_job_devices`, `dns_servers`, `wifi_history`, `client_history`, `mac_lookup`, `app_settings`, `bridge_status`, `bridge_port_status`, `loop_events`, `interface_state`, `bridge_vlans`, `vlan_labels`, `password_reset_tokens`, `device_address_proposals`, `ping_targets`, `ping_samples`, `client_signal_samples`, `speed_tests`, `speed_samples`, `traceroute_runs`, `device_uplinks`, `port_stats_1m`, `port_stats_1h`, `port_hosts`, `interface_relations`, `device_minutes` (one row per device-minute: coverage, CPU samples, NMS self-metrics; unix-second bucket, no FK, kept 14 d), `device_hours` (its hourly rollup, kept 730 d), `flow_sender_policy` (the flow block list, keyed by sender address; `source` is `deleted` or `auto`; an address is never also in `flow_exporters`), `flow_export_checks` (per device: flow sightings and the result of the one confirmation read), `flow_exporters`, `flow_exporter_ifaces`, `flow_points`, `flow_templates`, `flow_prefixes`, `flow_1m`, `flow_1h`, `flow_1m_meta`, `flow_1h_meta`

Long-running commands — `FetchSpeedTest` (`/tool/fetch` download measurement) and `Traceroute` (`/tool/traceroute`, one pass) — run on **dedicated one-shot connections** (`DialOnce` + `RunCommandWithTimeout`), never on pooled clients, because they exceed the pool's 30s `CommandTimeout` and would hold the per-client mutex
- **`internal/routeros/` sessions (P0-13)** — go-routeros v3.0.1 is **vendored and patched** in `backend/third_party/go-routeros` (its own module, `replace` in `backend/go.mod`; the README there lists every local change): reply caps checked before allocation (1 MiB per word, 32 MiB and 50,000 rows per reply), `ros.SessionFatalError` for a cap violation / `!fatal` / malformed word (the client closes itself), and **no dialers** — every session is opened by `routeros.dialSession` from a `routeros.Target{DeviceID, Address, Port, UseTLS, Pin}` (build it with `poller.DialTarget(dev)`) through `Pool.Dial`, `Pool.EnsureConnection`, `DialOnce` or `DialOnceWith`. **Deadlines**: connect 5 s, TLS handshake 10 s (15 s on C1), login 10 s, each command 10 s (15 s on C1, 30 s for the big table reads in `slowCommands` in `session.go` — **a new slow read must be added there** — and 30 s `OnceCommandTimeout`), the wait for the session included; an expiry on the wire ends the session, one while still queued fails alone (`IsSessionBusy`). **TLS pins**: `devices.pin_cert_sha256` is the lower-case hex SHA-256 of the leaf certificate (what RouterOS prints as `fingerprint`; `routeros.NormalizePin`); a TLS target without a pin is refused with `ErrPinMissing` before any connection, another certificate aborts the handshake with `PinMismatchError` — no login — and records a critical `tls_pin_mismatch` finding (alert rule of that name). There is no "verify" switch (`MIKROTIK_NMS_ROS_TLS_VERIFY` is retired; startup warns if set). **Pool**: dials run outside the lock, one per key (callers share it); after a failure a key backs off 15 s → 10 min ±20 % (a refused login or pin mismatch goes straight to 10 min); success, `Forget` and `ResetBackoff` (called when liveness sees a device answer again) clear it; a session leaves the pool when its connection closes, whoever closes it. Error helpers: `IsSessionFatal`, `IsSessionBusy`, `IsDialRefusal`, `IsLoginRefused`, `ErrSessionClosed`, `*TimeoutError`, `*BackoffError`. The library's logging goes through `clientLogHandler` (capped at Info, login secrets dropped). `observe.go`: every command and pooled dial reports to the one `routeros.Observer` (`SetObserver`; device, wall time incl. queue wait, rows, timeout) — one-shot sessions dialled with a `DeviceID` count against that device. `main` installs `poller.InstallRouterOSHooks(db)` (`SetWeakDeviceFunc`: C1, unprobed or light profile; `OnPinMismatch`). `routerostest` also offers `NewTLSDevice`/`Fingerprint`, `Target(id)`, `SetFatal`, `SetRaw`, `OversizedWord`, `OnCommand`, `Logins`
- **`internal/alerts/`** — minimal alerting, database-only (an alert never costs a device a command). `Rule`s (`rules.go`: `device_unreachable` = device status `offline`, critical; `parallel_api_poller` = a confirmed `device_findings` row seen in the last 2 h 15 min, warning) report `Observation`s; the `Engine` (`alerts.go`, every 30 s, started by the poller manager **only with `MIKROTIK_NMS_POLLERS=local`** — stale rows of a copied database must not page) keeps one open `alerts` row per (rule, key): opens, touches, resolves — never on a rule that returned an error — and notifies: on firing, every 4 h while unacknowledged, on resolve if the start was delivered; nothing delivered = retried next tick; silences (`alert_silences`, device/rule/site) stop notifications, not alerts. `Notifier` (`notify.go`) delivers to `notification_channels` — `smtp` through the shared mail settings (`mailer.ConfigFromSettings`), `webhook` as a JSON POST — whose targets are encrypted like device secrets and never returned by the API (`TargetHint`); errors never contain a webhook URL. Publishes WS `alerts.update`. Runbooks per rule in `docs/RUNBOOKS.md` (`alerts.RunbookURL`). A new rule = a `Rule` in `DefaultRules` + `RuleNames` + a runbook section. Further rules: `tls_pin_mismatch` (critical; from the finding the dial records) and the telemetry rules in `load_rules.go` on `device_minutes` / `port_stats_1m` — `cpu_high` (quiet-window minute averages: C1 ≥ 80 %, C2/C3 ≥ 85 % for 5 min warning; ≥ 95 % for 10 min critical), `mem_low` (free below 5 % of total, or below 8 MiB on C1, for 3 min), `port_egress_drops` (key `<device>|<iface>`; ≥ 100 tx drops and ≥ 0.1 % of packets in each of 5 consecutive minutes). A window fires when every minute is measured and bad, resolves when none is bad and at least one is measured, and otherwise the rule answers `Observation.Hold` — unknown is not healthy: the alert stays as it is and none is opened. A severity that rises re-notifies at once (an acknowledged alert stays quiet). `flow_export_on_switch` (`flow_export.go`): flow datagrams from the address of a device that must not export — a warning with `Observation.Unconfirmed` (`alerts.confirmed = false`, never critical: a UDP source address can be forged) until the collector's read of the device confirms the export, then critical with `facts.rollback`. **Escalation**: an alert that reaches a severity for the first time fires again and is notified at once, through an acknowledgement of the lower severity; one it was already announced at (`alerts.notified_severity`) is not news, so an alert swinging between warning and critical does not notify at every swing
- **`internal/firmware/`** — firmware availability without asking the devices: `Feed.Fetch` reads `https://upgrade.mikrotik.com/routeros/NEWESTa7.<channel>` (stable/long-term/testing/development; body `<version> <unix build time>`, size-limited, base URL injectable for tests) and `ParseVersion`/`UpdateAvailable` compare RouterOS versions (beta < rc < release; unparseable = no update)
- **`internal/kea/`** — minimal client for the Kea DHCP Control Agent (`lease4-get-all`); used by client discovery to enrich MAC → IP/hostname lookups when `kea_url` is set in app settings
- **`internal/flow/`** — built-in flow collector (`flow.Collector`; `Run` returns at once unless `MIKROTIK_NMS_FLOW_LISTEN` is set). One UDP socket per listen entry → allow-list by **source IP** (`flow_exporters`; a managed device's address is auto-accepted while `flow_auto_accept_devices` is on, everything else is added by an admin; unknown senders are only listed in an LRU ring, never decoded) → per-exporter + global token buckets (`flow_rate_limit_pps`) → a bounded non-blocking queue → **one worker goroutine** that owns all decoder and aggregation state (decode → normalise → aggregate, `recover()` per datagram) → a writer goroutine whose full channel drops the batch (ingest never blocks on SQLite). `flow/decode` is the **only** importer of goflow2 (`github.com/netsampler/goflow2/v2` v2.2.6, decoder packages only) and wraps it in guards (template/field/observation-domain caps, v5/sFlow prechecks, pending data-before-template with TTL, every value copied out of the read buffer), fuzzed by `FuzzDecode`; v9/IPFIX templates persist in `flow_templates` so a restart decodes at once. Normalisation: self-export drop, OPNsense duplicate filter, NAT inside view (RouterOS IPFIX post-NAT dst replaces dst, so WAN downloads show the LAN host), service-port choice (`flow/svcport`, shared with the API for app labels). Aggregation: each flow is split across minutes by overlap; per (exporter, minute) the top `flow_top_n` conversations per `(in_if, out_if)` plus one exact "other" row go to `flow_1m`, and `flow_1m_meta` records every minute the exporter was alive (absence = gap, not zero); a minute flushes at M+3 min, then rolls up hourly into `flow_1h` (+ `flow_1h_meta`). Also: RouterOS ifIndex→name sync every 5 min (`flow_exporter_ifaces`; names from the port-stats collector's interface snapshot and VLAN ids/parents from the VLAN rows of its stacking read (Tier 3c, `DeviceVLANs`), both via `UseIfaceSource` — the device is printed only before the collector's first read of it, and a failed VLAN read skips the sync instead of wiping the VLAN ids; learned hints for other exporters; manual names survive), the address plan `flow_prefixes` (internal/vpn/transit from managed devices' addresses, every 15 min; retried after 60 s while a device's uplink rows are still stale after a restart; uplink rows judged by `UseUplinkAge`, the map's per-device rule), and **native observation points** (`flow_points`, one per exporter interface with traffic; facing up/down from uplinks/VPN types or the admin-set iface role). `flow/pktgen` builds synthetic datagrams for tests and `cmd/flowreplay`. **Guardrails** (`flow/guard.go`, pure rules in `internal/flowguard/`): nothing is accepted automatically unless `flow_auto_accept_classes=router` (then only a router-role C3 device with fresh egress; `flow_auto_accept_devices` is dead and migration 031 sets it to `false`); a **blocked** sender (`flow_sender_policy`: an exporter an admin deleted, or a managed switch / AP-CPE / C1 device, blocked on its first flow datagram) is dropped before decode and counted; the first datagram from such a device also records a sighting and asks for **one** read of `/ip/traffic-flow/print` + `…/target/print` on its pooled session (`routeros.ReadTrafficFlow`; at most hourly per device, never while paused or with polling off; a confirmation is valid 2 h 15 min) — the collector's only device read besides the ifIndex sync. `flowguard`: `Judge` (eligible = a role that routes, probed, not on the light profile, budgeted C2 or C3), `NeverExports`, `AutoAccept`, `CheckCommands`, `ApplyCommands` (never `interfaces=all`), `Rollback` (profile first, disable the one target, `enabled=no` only if needed — with the kernel-crash warning and `/system package update download` before RouterOS 7.25, `fixedSince` — remove the target, verify; every `[find]` names the one target). `(*flow.Collector).UseAcceptHook` is the seam for the CPU watch after an exporter is accepted
- **`internal/flowview/`** — pure (no DB/I/O) query side of flows, used by `api/flows*.go`: point direction (`facing` up → download = in_if ∈ set; down → download = out_if ∈ set), row filters (`local_internal`, `exclude_attach`), endpoint classification (multicast → exporter self → `flow_external_prefixes` → `flow_internal_prefixes` → most specific plan prefix → known host in `mac_lookup` → external; RFC 1918 is **not** a blanket rule), grouping (src/dst/pair/conv/app with an exact "other"), **derived-view suggestions** (`Suggest`: gateway-host rule and router-trunk rule for switch ports that cannot export) and the measured Sankey
- **Device roles** (`internal/devclass/role.go`: `ClassifyRole`, pure; `internal/topology/roles.go`: `LoadDeviceRoles(db, uplinkAge, now)`, database only) — `router` (own internet or VPN egress in `device_uplinks`, probed C3), `weak-router` (the same with a smaller or unprobed CPU), `switch` (CRS/CSS and similar boards, whatever their routes), `ap-cpe` (an AP/CPE board, or an unknown board with radios, whose default route points at another router), `unknown` (anything the facts do not settle — never "router" by default), each with a reason an operator can read. A default route via a private or managed next hop is not an egress. On `GET /devices` and `/devices/{id}` as `role`, `role_reason`, `flow_export_eligible`; `topology.inferDeviceType(board, arch)` uses the same board families. - **`internal/poller/manager.go`** — orchestrates background polling goroutines:
  - **Per-device cadences** (`poller/cadence.go`, `schedule.go`; design Appendix B): every device-reading loop wakes every 5 s (`pollerTick`), re-reads the device list and runs, per device, only the **tiers** that are due (`devclass.Tier`: counters, ethernet, bridge_ports, bridge_vlan, logs, bridge_hosts, relations, neighbors, routes, arp, dhcp_leases, wifi_registrations, inventory, and the two CPU tiers `cpu` / `cpu_post`, which have no fleet floor). A tier's interval is `max(devclass.EffectiveInterval(effective class, profile, tier), fleet floor)` — the class cadence (C1 weakest … C3; unprobed = C1; the `light` profile = the C1 plan; a gentler `class_override` wins) **floored** by the setting/env that used to drive the whole loop, so an admin can still slow everything down but never push a device past its class; interval 0 = the read is not in the device's plan (DHCP leases run on C3 only). The next run is the **end** of the last one + interval ±10 % by the device's phase (`devclass.NextRun`/`Phase`; no catch-up — a slow run shifts the next one); a device without a pooled connection is retried after 30 s. `NewCadence(db, cfg)` builds the one `CadenceSource` (`Interval(dev, tier, now)`, `Paused(dev, now)`; settings-backed floors cached 5 s) the manager hands every loop via `UseCadence` (constructors default to the fleet-wide intervals). **Pause** (`polling_paused_until`): only liveness runs (and passive flow intake); every tier's interval is 0, and **nothing ages** — the port-stats snapshot/rates, link staleness, the network-health prunes, `port_hosts` (retention, `FreshPortHosts`), `device_uplinks` (`FreshUplinks` keeps a paused device's rows) and the neighbor sweep all hold a paused device's last read — and once a pause ends the network-health prunes give each tier a whole stale window to be read again; the counter-delta gap rule stays on the wall clock, so paused minutes are gaps (no rows). Firmware checks, connectivity probes/signal reads, scheduled speed tests, the clients scan and the flow ifsync/address plan skip a paused device (logged once per pause); a granted live stream stops at its next sample (the pause is read fresh, not from the policy cache); and the on-demand actions that would reach it (run-now speed test/ping/traceroute, `GET /devices/{id}/addresses`, firmware upgrade/channel/RouterBOOT, `/debug/wifi`, approving an IP auto-follow proposal) answer `409 polling paused until <time>` through `Server.writePollingPaused` — a firmware job already running is not interrupted. Each loop publishes every tier's next run into `poller.Schedule()`, which `GET /devices/{id}` (and the polling-control responses) return as `polling: {class, profile, paused_until, next_runs: {tier: time}}`; `poller.DevicePaused(db, id, now)` / `PausedUntil` are the predicates for code outside the loops; the API gets the manager's `CadenceSource` (`Manager.Cadence()` → `api.NewRouter`) so every staleness rule it applies is the loops' own
  - Health (liveness): 30s (env), a lightweight TCP "ping" (`routeros.Ping`, plain dial to the API port — bypasses the connection pool/mutex so it never contends with heavier pollers and doesn't flap on transient API slowness). Owns device `status`: a device is only marked `offline` after it has missed pings for longer than `offline_threshold_seconds` (app_setting, default 120s); within that grace window it reports `unknown` (surfaced as the gray "not responding" state) rather than flapping straight to `offline`. `last_seen` means *last successful contact* (not bumped on failed pings). The frontend renders the status triad — green `online` / red `offline` / gray `unknown`→"not responding" — via the shared helpers in `frontend/src/lib/status.ts`. Liveness runs for every device, paused or not.
  - Info refresh (Tier 6): per device every 60 min (`info_interval` app_setting as the floor), the heavy pass — one **proplisted** `/system/resource/print` (cpu/memory/uptime + version/board/platform/arch + cpu/cpu-count/cpu-frequency), cached in the DB, which also **probes the CPU class** (`poller/classprobe.go`: `devclass.ParseResourceFacts` → `Classify` with the highest frequency ever seen → `SetDeviceClass`). The first classification applies at once; a **change** only when probes at least **24 h apart** agree (every probe in between agreeing; pending candidate in memory), logged once and audited as `device_class_probed`. The same pass reads the firmware facts (proplisted `/system/package/update/print` + `/system/routerboard/print`, read-only — see Firmware below). It no longer prints the interface list: the `interfaces` table is kept by the port-stats Tier 0 read (below). Static details rarely change, so this runs rarely while the liveness ping keeps status fresh; the UI shows the cached values between refreshes. A freshly-added device (empty board/version) is enriched immediately on its first successful ping instead of waiting a full interval, and an online device that is still unclassified is re-probed every 5 min. The info pass never downgrades status — that's the liveness poll's job.
  - Topology: per device `/ip/neighbor` (Tier 3d; C3/C2 2 min, C1 5 min) and the default-route print (3e; C3 60 s, C1/C2 5 min), floored by `poller.TopologyFloor` (the `topology_interval` setting, 30 s..1 h, or `MIKROTIK_NMS_TOPOLOGY_INTERVAL` when that is set in the environment; 60 s); once per that env interval it runs the gateway attachment, IP auto-follow (`poller/ip_follow.go`, opt-in `auto_follow_ip`; recent sighting = within 2 of the reporting device's neighbor reads) and the topology builder, and broadcasts the graph via WS. **IP auto-follow only proposes**: a managed device's MAC sighted at another address becomes a pending `device_address_proposals` row (zero device I/O; superseded when the device address changes, expired after 24 h unsighted, one `ip_address_proposed` event when new) — MNDP is unauthenticated and the plain API sends the password before any identity check, so only an admin's approval (`POST /devices/address-proposals/{id}/approve`, fresh login) runs `poller.VerifyAndCommitAddressMove`: stored-credential login on a separate `<id>:verify` pool key, board/version/MAC check, conditional commit; the TLS-pin probe that could allow auto-commit is P0-13's (seam marked in `reconcileAddresses`). Per online device, concurrently on pooled clients, it runs Tier 0 (`GetInterfaceStats`) every counter interval (C3 15 s, C2 30 s, C1 60 s) and Tier 4a (`GetEthernetStats`) every 5 min; the per-device `tierInterval(dev, tier, now)` hook decides both — the manager's `CadenceSource` (`UseCadence`) with the fleet-wide `port_stats_interval` (default 15s, clamp 5..300, re-read each cycle) as the floor, 0 while paused — each next read counts from the end of the last (± jitter), and every interval-derived rule (delta gap, expiry, flush hold) uses the device's own interval; a paused device's snapshot and rates do not expire (the delta across the pause is still a gap). The Tier 0 rows are the per-device **interface snapshot** (`DeviceSnapshot(id) (rows []routeros.InterfaceSnapshot, at, ok)` — Tier 4a merged by name, served while ≤ 3× the device's interval old; `DeviceIfaces(id)` adds the ethernet read time and `CommandsLastMinute`, the commands this collector sent the device in the last complete minute) that the port monitor, uplinks and flow ifsync read, and they keep the `interfaces` table current (rows upserted when an inventory field changes and all hourly, rows gone from the print pruned in the same transaction; an empty print never wipes a device). A second loop dumps each online device's bridge FDB (non-local, non-disabled entries; Tier 3b: C3 5 min, C2 10 min, C1 15 min) into `port_hosts`, and its interface stacking (3c: C3 5 min, C2/C1 15 min) — bond members (`/interface/bonding` slaves) and VLAN/PPPoE-client carriers — into `interface_relations` (the VLAN rows with their vlan-id are also kept in memory for the flow ifIndex sync, `DeviceVLANs`), each floored by `port_hosts_interval` (default 300s, clamp 60..3600), retrying devices without a pooled connection yet (cold start) after 30s; it never writes `mac_lookup`. An FDB row is current for 3 of its device's dump intervals (≥ 15 min; a paused device's against its newest dump): `FreshPortHosts`, used by the gateway attachment and the traffic role graph (`api/traffic_path.go`). A Tier 0 read that could not start for want of a pooled connection is due again at the next wake-up, not an interval later. The API derives per-port roles (wan/uplink/downlink/peer/access/wireless/vpn/virtual/idle — `peer` = an up link to another managed device that is not a tree edge, e.g. anchor↔anchor or a redundant/ring link; bond members take their bond's role with `master` set; the physical carrier under a VLAN/PPPoE WAN is an `uplink`), the Internet→port path and an **estimated** Sankey (a tree plus `local:<dev>` "east-west" source nodes so every device conserves flow) from `links` + `device_uplinks` + `port_hosts` + `interface_relations` + these rates via `topology/path.go`. Each device's uplink faces its own default-route egress first, then the first anchor, then the port hearing most devices. A minute/hour with no row fleet-wide is collector downtime: served as a gap (`null` rates) and excluded from averages/p95

### Key patterns

- shadcn/ui in this project uses **base-ui** (not Radix). Use `render={<Component />}` instead of `asChild` for composition.
- JSX text: Next 16.2's SWC drops the leading space of a **multi-line** text node that contains an HTML entity (`</span> with this⏎device&apos;s …` renders "…</span>with this"). Put an explicit `{" "}` after the element in that case.
- Frontend API/WS base is **same-origin by default** (the reverse proxy serves `/api/*`); `NEXT_PUBLIC_API_URL`/`NEXT_PUBLIC_WS_URL` are optional build-time overrides for split-origin deployments only — leave them empty otherwise (a stale baked URL breaks every page with "Failed to fetch"). `next dev` on port 3000 auto-targets `<hostname>:8080`. Network-level fetch failures surface as `ApiError(0, …)` naming the resolved target.
- Device credentials in `devices.password_enc` are encrypted at rest (AES-256-GCM, `internal/crypto`, `enc:v1:` prefix) and **fail closed**: `MIKROTIK_NMS_ENCRYPTION_KEY` is required with `MIKROTIK_NMS_POLLERS=local` (startup error otherwise; `install.sh` generates one, `make dev-backend-poll` uses a fixed dev key), `queries.CreateDevice` / `SetDevicePassword` return `ErrSecretStorage` instead of storing plaintext (plaintext only with the dev flag `MIKROTIK_NMS_DEV_PLAINTEXT_SECRETS`, refused while polling; test packages opt in through `main_test.go`), and `UpdateDevice` never touches the password. A stored value that cannot be decrypted reads as `crypto.Unreadable`, which `Pool.Dial` / `DialOnce` refuse with `ErrCredentialsUnreadable` — no login is tried with an empty or garbage password — and startup logs the count. Plaintext rows are encrypted on startup. There are **no default RouterOS credentials** (`MIKROTIK_NMS_DEFAULT_ROS_USER`/`_PASS` are gone; `POST /devices` requires username and password), and editing or deleting a device calls `pool.Forget` when the address, port, TLS flag, username or password changed.
- Topology links are **derived** from raw neighbor data in the `neighbors` table, stored in `links` table. Rebuilt on each topology poll cycle.
- Traffic analytics is always-on and cheap: one `/interface/print` per device per `port_stats_interval` (not a `monitor-traffic` stream per port). The per-interface `monitor-traffic` stream is on-demand and class-capped: it starts once a `traffic.<id>.<iface>` subscription is granted (1 s on C3, 15 s and admin-only on C1). Every other live view (map links, port grid, `/traffic/ports/*`) reads the snapshot; tests prove a read path device-free by dialling the pool to `routeros/routerostest` (a fake API endpoint that records every command after login). Port endpoints take `device`/`iface` as query params (`/traffic/ports/history?device=&iface=`) because interface names can contain spaces/slashes. Direction: `rx` = into the device through the port, `tx` = out of it; download is `rx` on wan/uplink/vpn ports and `tx` on downlink/access/wireless ports; peer/virtual/idle ports show raw in/out.
- Flows are **measured per exporter and never summed across exporters** (the same packet is often seen by a firewall and a router, or both ends of a trunk); every view is one observation point = one exporter + a set of its ifIndexes. Native points are created by the collector; **derived** points represent ports of switches that cannot export (hardware-offloaded forwarding) from a neighbouring exporter and are added by admins from `flowview.Suggest`; coverage = flow bytes / Phase 1 port-counter bytes over the buckets both cover. Flow fact tables (`flow_1m`, `flow_1h`, `*_meta`) use **INTEGER unix-second buckets** and **BLOB IPs** (4 bytes IPv4, 16 bytes IPv6, v4-mapped unmapped first; the folded "other" row is the empty blob `x''` — bind `[]byte{}`, never `nil`), have no FKs for size, and `flow_exporters`/`flow_points` ids are `AUTOINCREMENT` so a deleted exporter's orphan rows (swept later) never attach to a new one. ifIndex 0 = router-local, never a row or point member.
- WiFi join/leave/roam events have two sources: **wireless log lines** (authoritative — parsed from `/log/print`) and **registration-table snapshots** (safety net). Each row in `wifi_history` records its `source` (`log` / `snapshot` / `absence`) so the UI can show provenance.
- Bridge log parsing is best-effort: regex patterns in `routeros/bridge_logs.go` look for "loop detected" / "MAC flap" / "BPDU on edge". Patterns are deliberately loose; new RouterOS versions may emit phrasing that needs regex updates.
- App settings (`app_settings` table) are runtime-tunable via the **Settings** page; backend pollers that read from this table (wifi_interval, client_discovery_interval, connectivity_interval, connectivity_ping_count, speedtest_interval, traceroute_loss_threshold, kea_url, DNS servers, port_monitor_*, offline_threshold_seconds, info_interval, tcn_storm_threshold, port_stats_interval, port_hosts_interval, port_stats_1m_days, port_stats_1h_days, port_hosts_stale_days, and the flow collector's flow_top_n, flow_top_n_hourly, flow_max_rows_per_minute, flow_1m_days, flow_1h_days, flow_rate_limit_pps, flow_auto_accept_classes, flow_internal_prefixes, flow_external_prefixes, flow_resolve_ptr, flow_advertise_address — re-read on its 30 s reconcile or per request) pick up changes on the next cycle without a restart. `topology_interval`, `network_health_interval` and `retention_days` are settings too (`poller.TopologyFloor`, `NetworkHealthFloor`, `RetentionDays`): **an environment variable that is set fixes the value** (`config.EnvLocked`; the page shows the field read-only), unset the setting applies within seconds; `poller.AdoptIntervalSettings` runs once per database and sets the three keys to what was in force, so a value typed into a once-dead field never springs to life. `wifi_interval` is clamped to 15 s..1 h, `client_discovery_interval` to 5 min..24 h. Liveness (`MIKROTIK_NMS_HEALTH_INTERVAL`), the firmware feed age and the flow collector's `MIKROTIK_NMS_FLOW_LISTEN` are env-only and require a backend restart. The per-device read intervals among them (`port_stats_interval`, `port_hosts_interval`, `wifi_interval`, `client_discovery_interval`, `info_interval`, `MIKROTIK_NMS_TOPOLOGY_INTERVAL`, `MIKROTIK_NMS_NETWORK_HEALTH_INTERVAL`) are **floors**: each device runs its class cadence when that is slower (see Per-device cadences).
- Continuous deploy to the LXC has two complementary paths: a **HMAC webhook agent** (`backend/cmd/deploy-agent` + `deploy/webhook-agent/`) and a **self-hosted GitHub Actions runner** (`deploy/lxc/runner-install.sh` + `.github/workflows/deploy-lxc.yml`). Both call `install.sh --skip-deps`; the runner path is gated by a narrow sudoers grant to `/usr/local/sbin/mikrotik-nms-deploy` (a wrapper that validates the workspace before forwarding to the installer).
- **Device I/O fence** (`routeros/policy.go`): `main` installs `routeros.SetDialPolicy` from the config before anything runs; `Pool.Dial`, `DialOnce`, `Ping`, `ScanSubnet` and `ScanMNDP` all call `CheckTarget`/`PollingAllowed`, so **new code that reaches a device must go through them, never `net.Dial` or the go-routeros dialers directly**. With `MIKROTIK_NMS_POLLERS=off` the manager starts only the DB-only jobs (retention, port-stats startup rollup) and the flow collector never binds; on-demand API actions map `ErrPollersOff` → `503` and `ErrTargetNotAllowed` → `403` via `writeDialPolicyError` (and a paused device → `409` via `writePollingPaused`); the login watch's outbound-address lookup (`routeros.OutboundAddress`) is fenced the same way. `/health` reports `pollers` (the UI banner), the authenticated `/system` adds `allowed_target_cidrs`. `install.sh` writes `local` + the LXC's own subnets (`--target-cidrs` overrides) and appends them once to existing env files.
- First-run: `POST /api/v1/auth/setup` creates the initial admin user (only works when 0 users exist).
- The client address (login rate limit) comes from `clientIP` in `api/security.go`, never from `middleware.RealIP`: the TCP peer, or — only when the peer is in `MIKROTIK_NMS_TRUSTED_PROXIES` (default loopback; set it to the ingress/proxy range in K8s) — the right-most `X-Forwarded-For` entry that is not itself a trusted proxy. `X-Real-IP` is ignored.
- The flow collector is **off everywhere unless configured**: code default `""`, `install.sh` writes `# MIKROTIK_NMS_FLOW_LISTEN=:2055` commented (new env files, and appended once to existing ones), Compose/K8s/`.env.example` ship it commented or empty, and the K8s UDP Service lives in `deploy/k8s/optional/` so `kubectl apply -f deploy/k8s/` never creates it. Device-side setup (RouterOS IPFIX, OPNsense NetFlow v9, derived views) is documented in `docs/FLOW-EXPORT.md`.
